## Evidence and implementation choices

- **Approval and lifecycle:** read-only hotfix diagnosis precedes authorized implementation, then actual lead/QA/producer and QA re-entry gates precede release. Denied implementation stopped in a fresh-agent sample with only an authorized investigation record changed. Narrative now has an explicit approve/revise/stop checkpoint. Full/lean/solo keep their own reviewer requirements and coordinator responsibilities. Two inherited hotfix/dev-story behavior specifications were corrected to avoid teaching future maintenance to bypass gates or auto-close implementation.
- **ADR freshness and size:** per-file SHA256 detects uncommitted and same-day changes that commit-date freshness can miss. Current Accepted status and hash are checked before summary reuse; stale/legacy stories reload focused current sections. The reader defaults to 8,000 Unicode content characters per page (maximum 12,000), reports missing sections and pagination, and can reject changed-file pagination via expected SHA256. It still reads/hashes the full file in process memory; metadata/index output is not covered by the content-page bound. A fresh sample reconciled an obsolete speed-8 summary against a 420,571-character ADR using 458 relevant content characters, implemented speed 12 and left story closure pending.
- **Routing and models:** generated entries explicitly dispatch real roles from `agent:` metadata; unknown roles fail generation. Coordinators retain question handling. The [Claude skill documentation](https://code.claude.com/docs/en/skills) explains that `agent` selects a subagent with `context: fork`; Codex uses its own routing rather than blindly adding that metadata. [Codex custom-agent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) describes role files and override precedence. Default generated roles omit model/effort overrides, allowing host spawn defaults and then parent selection. This does not eliminate host context limits or validate every native role.
- **Sprint feasibility:** prerequisites include scenes/assets/services/tests and their transitive dependencies, not only story logic. A fresh solo sample identified absent startup/scene/input work, scheduled it before a playable goal within provisional capacity and explicitly stated that the demo was not currently runnable. Estimates were not validated against velocity and no game implementation was produced by this planning test.
- **Safe updates:** [Git merge documentation](https://git-scm.com/docs/git-merge) describes unrelated-history merging as overriding the normal common-ancestor requirement. [Git apply documentation](https://git-scm.com/docs/git-apply) explains non-applying `--check`, original-blob requirements and possible `--3way` conflicts. The revised guide uses the exact adopted baseline, selected paths and explicit conflict review. Six real local Git fixtures passed; no blanket overwrite or conflict-free guarantee is made.
- **External issue scope:** all 417 locked files were searched for `\bdmf(?:\.input)?\b` and `image[-_]pen`; no matches were found. No DMF/Luau input runtime or image-pen implementation exists in this shipped source to patch. This finding does not assess external installations.

[Operating guidance](operating-guide.md) covers delegated reversible decisions, a small observable playable loop and Unity routing while preserving other engines. New engines, board synchronization, creative MCP, paid asset backends and NPC TTS need separate implementation and acceptance.
