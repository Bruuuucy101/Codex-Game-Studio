# NPC voice production — design

Addresses the concrete missing execution in upstream issue14. Preserve original
`localize vo-pipeline` scan/script/validate/integrate and audio role boundaries.
The user delegated product decisions. Choose baked dialogue with existing selected
voice IDs; runtime synthesis, cloning, timestamps and pronunciation dictionaries
remain explicitly outside this initial contract.

## Outcome

Two or more NPCs can have stable distinct voice IDs. Explicit dialogue keys and
locales produce actual playable WAV files and a game-consumable manifest. Repeating
an unchanged request reuses verified owned audio; changing one line/settings changes
only that line's generation identity. Generation, listening review and engine
import remain distinct evidence.

## Global Constraints

- Preserve original417-file provenance and all existing studio identities. Extend canonical workflow sources and regenerate wrappers; never edit generated content directly.
- Python3.10+ standard library, reuse existing asset HTTP/journal/path/publication helpers where their exact interfaces fit. Do not require Pillow for WAV-only commands. No duplicate generic transport/journal framework.
- Fixed HTTPS api.elevenlabs.io, credentials only ELEVENLABS_API_KEY via xi-api-key. No secrets in distributed clients, logs, requests on disk, or artifacts. No global config changes or live paid calls during implementation.
- Strict project-confined JSON inputs, source hashes, no symlink/traversal or output overwrites. Private state under ignored .ccgs-assets/voice/, restrictive permissions. Default plan/bake/collect operations have no writes/network unless explicitly selected.
- Each line is a synchronous journaled submission. Persist intent before POST; never automatically retry any uncertain POST. Completed audio is durable before marking generated. Uncertain lines remain blocked; successful other lines remain usable. Local coordination does not imply remote exactly-once semantics.
- Evidence must distinguish fixture HTTP and valid audio decoding from live provider quality, listening approval, and actual game-engine import.

## Input and CLI

`voice plan --request PATH` validates offline. `voice bake --request PATH [--write]`
plans by default; write performs read-only account eligibility checks then only
missing explicitly requested line operations. `voice status --request PATH` reads
local line receipts without provider calls. `voice collect --request PATH [--write]`
publishes verified generated audio plus immutable versioned playback manifest;
it never starts generation. `voice voices` and `voice models` are explicit remote
read-only discovery commands. `voice verify --manifest PATH` resolves every file,
checks declared hash/PCM properties and reports missing/corrupt/duplicate entries.

Schema1 request has provider:elevenlabs, model_id:eleven_multilingual_v2,
output_format:wav_24000, source_files:[...], rights_note:string,
npcs:[{id,voice_id,voice_settings:{stability,similarity_boost,use_speaker_boost?}}],
lines:[{key,npc_id,locale,text,direction_notes}], and optional standalone:true.
Stable NPC IDs/slugs and opaque bounded voice IDs; line keys must start dialogue.
Exact Unicode text is hashed/sent without silent normalization or substitution.
No unresolved {placeholder} dialogue: initial scope accepts final spoken text only.
Locales use a conservative BCP47 subset and cannot be path fragments. Model cannot
be silently substituted. Every requested NPC must have a distinct voice ID.

Canonical mode requires real source files in design/narrative/ or
production/localization/ and assets/data/strings/, retaining full raw source hashes.
The workflow explicitly cross-checks each selected dialogue key/text/locale against
those actual source records before writing a reviewed request; CLI does not claim
that arbitrary string-table schemas can be automatically parsed. Standalone mode
is explicit and may omit sources. Text length1–2000 Unicode codepoints, max200lines,
max100NPCs, total200000characters, bounded request4MiB/source2MiBx32. Bool/nonfinite
numeric settings, duplicate keys/line+locale pairs, unknown fields, missing NPCs,
empty text and malformed data fail before network. Stability/similarity in[0,1],
speaker_boost boolean only; omitted fields remain omitted in the wire request.
Style/speed/seed/dictionaries are unsupported until separately verified.

Write-time eligibility: paginate GET/v2/voices with has_more/next_page_token,
not total_count, enforcing bounded pages and no repeated cursors; each selected
voice ID must exist. GET/v1/models must contain the selected model and true
can_do_text_to_speech. Check selected locale primary language against model
languages[].language_id. Conservatively apply the smallest positive documented
request-character limit, without guessing account tier. If speaker boost is
requested require can_use_speaker_boost. An available voice/model is not proof of
billing entitlement or rights; provider errors remain visible categories.

Generation is exactly POST/v1/text-to-speech/{encoded_voice_id}?output_format=wav_24000
with {text,model_id,voice_settings}. MultilingualV2 does not support language_code;
locale stays local metadata. Response is synchronous bytes, not an invented task
ID. OpenAPI's generic audio/mpeg content type is insufficient evidence: inspect
actual WAV bytes and reject any different codec. The narrow collector requires
RIFF/WAVE PCM,24kHz,16bit,1or2channels, positive complete frame count, bounded64MiB
and maximum10minutes. Validate chunk/frame sizes and fully read data. Do not accept
an MP3 merely named .wav or a truncated WAV whose header parses.

## Identity, freshness and recovery

A deterministic per-line request hash covers schema, provider/model/voice, exact
text, locale, supported settings and output format. Line operation identity also
includes NPCID and dialogue key; output filenames retain a safe readable key prefix
plus the full request hash to avoid truncation collisions. Batch/source revision
is separate: unrelated source-file changes must not regenerate unchanged lines.
The new batch manifest records current source hashes and each reused audio's
original generation provenance. This avoids claiming old audio was newly generated
from the latest source revision. Cache hits require a valid owned receipt and
actual artifact hash/PCM properties, never filename/content hash alone.

Each bake preflights all input/output paths and model support before any POST.
Journal and lock each deterministic line identity; source freshness is checked
before each new submission and again before manifest publication. A source edit
mid-batch stops remaining generation; completed lines retain their provenance.
A known generated/collected line reuses bytes; pending/submitting/unknown cannot
silently resubmit. Repeat bake on a partially failed batch reports each line state
and makes no uncertain/failed replay. Deliberate regeneration must require an
explicit request revision/nonce field (include in hash) documented as another paid
operation, never random IDs assigned automatically. Add optional generation_revision
string for this exact purpose, default absent.

Use existing asset staged-inode/create-only hard-link ownership/recovery protocol
for output WAV and manifest, including identical-byte competitor detection. Output
under assets/audio/vo/{locale}/. Manifest path is assets/audio/vo/manifests/{batchhash}.json;
no mutable latest pointer or removal of older files. Publishing manifest last
means it contains only a complete requested batch. Partial line receipts remain
inspectable but no success manifest is emitted with absent audio. Manifest maps
(locale,key) to npc_id,voice_id,model_id,request_hash,path,sha256,PCMproperties,
source provenance,rights note and pending listening/import statuses. No credentials
or raw remote errors. Two distinct voices are an identity guarantee, not a claim
that listeners can distinguish model outputs without listening.

## Verification and workflow

A local HTTP fixture serves paginated voices/model metadata and different valid
PCM audio per selected voice; actual CLI calls prove payloads, output decoding and
restart behavior. Cases: twoNPCs/multiplelines, unchanged0POST, onechangedline1POST,
changedvoice/settings/locale/revision invalidation, source-onlychange0POST with
updated manifest provenance, response-loss0automaticretry, mixedsuccess/failure,
concurrency, corruptaudio, wrongrate/codec, missingcredentials, deniedmodel/voice,
malformedpagination, missinglanguage, protectedpath/identical-bytecollision.

A small engine-neutral playback-manifest loader example and executable fixture
must resolve all selected files and decode them; label it loader acceptance, not
engine-specific import. Add a `npc-voice` workflow whose coordinator executes,
audio-director/localization-lead review scripts and listening, and engine owner
imports. Do not grant forbidden audio generation to existing specialists. Preserve
full/lean/solo behavior and truthful blocked stages. Include recorded-audio fallback
through existing localization workflow when no service is configured.
