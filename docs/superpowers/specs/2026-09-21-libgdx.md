# libGDX specialist set and runnable starter — design

Implements upstream [#105](https://github.com/Donchitos/Claude-Code-Game-Studios/issues/105) under the user's delegated product/technical authority. Preserve its lead-plus-four-domain shape while correcting inaccurate implementation advice using official libGDX sources.

## Outcome

`/setup-engine libgdx VERSION` configures the engine, language, real selected backends, version references and specialist routing. All five roles are complete and registered: `libgdx-specialist`, `libgdx-scene2d-specialist`, `libgdx-graphics-specialist`, `libgdx-ashley-specialist`, `libgdx-core-specialist`. Java/Kotlin source and multi-module layouts participate in onboarding, stage detection, rules, implementation and review. A Java desktop/headless starter provides reproducible simulation/lifecycle/build acceptance.

## Global constraints

- Preserve all original baseline identities, lock bytes, deliberate patch provenance and prior web/tooling/board additions. New canonical roles generate full Codex native profiles and source references.
- Engine ID is `libgdx`; `libktx` means libGDX with an explicitly configured Kotlin/KTX choice, not another engine. Never fabricate a compatible Kotlin/KTX version or claim it was executed without evidence.
- Tested starter pins: libGDX `1.14.2`, Gradle `8.14.3`, JUnit Jupiter `5.13.4`, build JDK `21`. Commit the real Gradle wrapper and distribution SHA256 `bd71102213493060956ec229d946beee57158dbd89d0e62b91bca0fa2c5f3531`. Direct versions are exact; dependency locks record resolved runtime/test graphs.
- Starter modules are `core`, `lwjgl3`, `headless`; Java source targets release 8 where supported by this small starter while the build uses JDK 21. Android/iOS/GWT are selected optional backends requiring actual SDK/toolchain validation, not automatically verified platforms.
- libGDX HeadlessApplication is a separate backend with mock graphics/audio/input. Actual lifecycle and simulation tests do not certify GPU rendering, audio, mobile or Kotlin behavior.
- No global JDK/configuration changes, unverified downloads, arbitrary package installation, copied binary engine assets or billable integrations. Downloaded official build tools remain task-local with recorded hashes.

## Roles and routing

Lead owns overall engine/platform/version decisions, reports through lead-programmer/technical-director and delegates to four real subs. Scene2D owns Stage/Table/Skin/input/layout/viewport; graphics owns SpriteBatch/ModelBatch/shaders/FBOs; Ashley owns optional ECS plus Box2D integration and fixed-step/collision rules; core owns lifecycle/files/input/audio/network/AssetManager/Gradle/backends. Preserve original tool allowlists and collaboration protocol; explicit `rg --glob '*.java' --glob '*.kt'` avoids type-name assumptions.

Correct the proposal's traps: overriding Actor.draw is valid under Stage/Batch ownership; headless is not a LWJGL3 flag; AssetManager-owned shared resources are unloaded/released through their owner, not disposed by every screen; Game.setScreen does not automatically dispose old screens; no blanket performance/pooling dogma without profiling. Box2D/Ashley/KTX remain optional dependencies with separately checked pins. Cross-platform APIs/language levels must be checked against selected backends.

VERSION/reference modules include official source links and dated verification, distinguishing documentation from runtime evidence. Existing project pins win over starter defaults. Setup records concrete build/runtime versions and actual platforms; it does not silently upgrade older projects. Role test specs include wrong-engine/defer/version cases and domain-specific ownership/lifecycle traps.

## Starter and integration

`templates/libgdx/` holds a minimal data-driven collect simulation, desktop renderer/input loop, headless lifecycle runner, tests, Gradle wrapper/config/dependency locks and README-LIBGDX.md. Config under assets/data is the single balance source. The common simulation is deterministic with bounds/normalized movement/collection/reset and injectable input/time, not static Gdx-dependent game logic. Desktop graphics resources have explicit ownership and dispose correctly.

`python3 tools/ccgs_codex.py scaffold-libgdx --target PATH [--write]` reuses the already tested safe scaffold copy operation: read-only preview by default, explicit manifest, no overwrite, symlink/traversal/protected metadata rejection, no installation. Binary wrapper bytes and executable wrapper mode are preserved. Existing studio README/.gitignore are not overwritten. Setup delegates copy/build under existing role permissions.

Java/Kotlin roots `core/src`, `lwjgl3/src` and selected platform modules are recognized alongside existing `src`; bundled templates, examples, build directories and vendored files do not make a pristine studio a game. Extend applicable rules conservatively to actual module game code and preserve existing scopes. New paths must not bypass gameplay/UI/data safety just because they are module-prefixed.

## Acceptance

All five roles/native profiles/reference modules/specs resolve; original branches and review modes remain. Routing uses specific subsystem/path context, with lead fallback for ambiguous `.java`/`.kt`, not extension-only claims of Scene2D/ECS. Source/detection/rule tests prove actual root/module behavior.

From a clean copied starter, run pinned Gradle under recorded JDK: core unit tests, actual HeadlessApplication lifecycle/simulation test and desktop compilation/distribution. Headless tests use bounded synchronization, propagate background-thread failures, stop the application and restore/isolate Gdx static state; a plain pure simulation test is insufficient to claim backend execution. Tests verify collected score, reset, lifecycle create/render/pause/dispose as observed. Record exact engine/JDK/Gradle versions, dependency locks and template hashes. A desktop playtest is additional evidence only if actually performed; otherwise explicitly unverified. CI adds a JDK 21 job with wrapper validation and real headless/build checks, gating release.
