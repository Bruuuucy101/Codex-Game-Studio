> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete lead-plus-four libGDX specialist support and a tested desktop/headless starter.

**Architecture:** Canonical engine roles/references and scoped workflow/rule integration, plus a conventional Gradle multi-module Java example copied by the existing safe scaffold utility.

**Tech Stack:** Python stdlib adapter; libGDX 1.14.2; Gradle 8.14.3; JDK 21; JUnit 5.13.4.

**Spec:** `docs/superpowers/specs/2026-09-21-libgdx.md`

## Global Constraints

- Preserve all original baseline identities, lock bytes, deliberate patch provenance and prior web/tooling/board additions. New canonical roles generate full Codex native profiles and source references.
- Engine ID is `libgdx`; `libktx` means libGDX with an explicitly configured Kotlin/KTX choice, not another engine. Never fabricate a compatible Kotlin/KTX version or claim it was executed without evidence.
- Tested starter pins: libGDX `1.14.2`, Gradle `8.14.3`, JUnit Jupiter `5.13.4`, build JDK `21`. Commit the real Gradle wrapper and distribution SHA256 `bd71102213493060956ec229d946beee57158dbd89d0e62b91bca0fa2c5f3531`. Direct versions are exact; dependency locks record resolved runtime/test graphs.
- Starter modules are `core`, `lwjgl3`, `headless`; Java source targets release 8 where supported by this small starter while the build uses JDK 21. Android/iOS/GWT are selected optional backends requiring actual SDK/toolchain validation, not automatically verified platforms.
- libGDX HeadlessApplication is a separate backend with mock graphics/audio/input. Actual lifecycle and simulation tests do not certify GPU rendering, audio, mobile or Kotlin behavior.
- No global JDK/configuration changes, unverified downloads, arbitrary package installation, copied binary engine assets or billable integrations. Downloaded official build tools remain task-local with recorded hashes.

## Review Focus

- A Java file under core/src must receive game rules and detection while bundled starter source does not configure the studio; contract fixtures pin both.
- Stage/AssetManager ownership errors must not double-dispose shared resources; role specs include explicit trap cases and starter tests inspect actual lifecycle.
- Headless background exceptions must fail the build instead of leaving a green test or hanging process; bounded failure-propagation test is required.
- Wrapper and dependency pins must recreate the build in a clean directory; clean-copy wrapper/headless/distribution acceptance is required.
- Existing Kotlin/other backend projects must not be silently rewritten to Java desktop defaults; setup policy and behavioral specs preserve selected pins/language/platforms.
